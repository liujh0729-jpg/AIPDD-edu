# 智能硬件模式（ESP32 外设）需求方案

> 状态：**关键决策已确认（见 §10），待最终 go-ahead 后并入主 PRD《AI语音家教-需求文档.md》作为 F10 并开始实现**
> 版本标记：v0.14（拟）
> 日期：2026-11-04

---

## 1. 背景与目标

现有产品以「电脑自带摄像头 + 麦克风 + 音箱」为感知与交互载体（见 F1/F2、硬件依赖）。本方案新增一种**外设化的交互形态**：用一台运行固件的 **ESP32 开发板**替代电脑的摄像头与麦克风，作为「离身的眼睛和耳朵」，把现场图像与语音**回传到电脑**，由电脑侧的 App 走**已配置的模型网关（F6）**调用大模型处理，并把结果按用户选择的**音响输出路径**播放出来。

**一句话：ESP32 只是 IO 前端（采集 + 可选播放），所有 AI 编排与模型调用仍在电脑本地完成，不改变"零登录 / 数据本地留存 / 凭证不落盘 / 无自动计费"的约束。**

目标（可验收）：
- G1 顶栏新增第三个 Tab「**智能硬件**」，位于「Agent」之后。
- G2 在同一 WiFi 下**发现并连接** ESP32 硬件，选择设备后进入工作态。
- G3 连接后，图像与音频由 **ESP32 回传**，替代本机摄像头/麦克风，复用 F1（视觉）与 F2（语音）链路。
- G4 处理统一经 **F6 网关**访问大模型，不新增厂商绑定。
- G5 **音响输出路径可配置**：电脑音响 vs ESP32 开发板所接音响；且与拾音端联动，避免自我拾音。

非目标（本期不做）：多设备并发、跨网段/公网连接、云端中转、设备 OTA 固件升级（列为后续）。

## 2. 名词与硬件前提

| 名词 | 说明 |
|------|------|
| 硬件端 / 设备 / ESP32 | 运行本项目固件的 ESP32-S3 开发板，承担采集与（可选）播放 |
| 主机 / 电脑 / App | Electron 桌面壳（现有），承担编排、网关调用、UI |
| 回传（Uplink） | 设备 → 主机：图像帧、麦克风音频 |
| 播放（Downlink） | 主机 → 设备：TTS 音频（仅"ESP32 音响"路径需要） |
| 音响输出路径 | TTS 最终从哪个扬声器出声：电脑 或 ESP32 所接音响 |

**目标硬件（用户已确认）：同时带 摄像头 + 麦克风 + 喇叭** —— 因此"电脑音响"与"ESP32 音响"**两条输出路径均可用**。
- 采集：ESP32-S3 + 摄像头（如 OV2640）+ 麦克风（PDM/I2S）。
- 播放：I2S 功放（如 MAX98357A）+ 小喇叭，支持 TTS 音频下行播放（路径二）。
- 具体板型/引脚：待你提供或我方在参考固件中给出（见 FR-10.7）。
- 能力位（📷🎤🔊）机制**保留**：用于兼容其它不全带的板型，此时对应路径据能力位置灰（见 FR-10.6c）。

## 3. 交互与体验（顶栏变更）

- 顶层导航由「沉浸式学习 / Agent」两按钮 → **「沉浸式学习 / Agent / 智能硬件」三按钮 + 右侧设置齿轮**。
- 「智能硬件」为**设备接入与外设工作模式**入口：进入后展示设备发现/连接面板；连接成功后该模式成为"以 ESP32 为眼耳"的工作态。
- 与现有三端关系（正交，不互斥）：
  - **智能硬件 ≠ 新的一"端"**，它是一种**采集/播放通道切换**。学习端（F5 沉浸式）与 Agent（F8）的处理逻辑不变，只是**感知源与发声源**从本机切到 ESP32。
  - 建议交互：进入「智能硬件」Tab 后选择一个具体模式意图（如"用外设进行沉浸式学习"），其内仍复用学习端主循环，感知/发声走设备通道；需要深度引导时照常路由 Agent（F8）。
- **设备操控面板（电脑端远程控制，FR-10.10）**：连接后智能硬件 Tab 内提供对远程设备的下行操控——开始上课/下课/暂停/继续、触发抓拍、静音/音量、状态灯与"我在听"提示音、主动播报、休眠/唤醒。这些动作与语音指令集（3.2）**双入口等效**：既能由孩子语音触发，也能由电脑端操作触发（呼应学习端 FR-5.1"按钮兜底"原则）；会话状态以电脑端为准，设备为薄 IO+执行器。
- **回改点**：FR-5.0b 顶层导航、FR-5.1/FR-5.2、技术架构"界面"行、AC-16（两按钮 → 三按钮）。

## 4. 功能需求（F10 · FR-10.x）

### FR-10.1 设备发现（同一 WiFi 局域网）
- 10.1a **主发现方式：mDNS/Bonjour**——设备固件广播约定服务（建议类型 `_dt hw._tcp` 或服务名 `deeptutor-esp32`，携带 name/IP/port/能力位：是否有摄像头/麦克风/喇叭）。主机侧用 Bonjour 浏览器枚举。
- 10.1b **备发现方式：UDP 广播信标**——设备周期性在约定端口广播 `{设备ID, IP, port, 能力}`，主机监听（跨部分 mDNS 受限环境的兜底）。
- 10.1c **手动兜底：输入设备 IP** 直连（发现失败时）。
- 10.1d 发现面板展示：设备名 / IP / RSSI(若可得) / 能力标签（📷🎤🔊）/ 在线状态；支持"重新扫描"。
- 10.1e 仅在**本机所在局域网子网**内发现；不提供跨网段/公网发现（安全边界）。

### FR-10.2 连接与配对
- 10.2a **配对与鉴权**：首次连接需配对——约定**共享 Token/PSK**（在设备配网时或设置中一次性录入；主机侧存 **Keychain / 0600**，遵循 FR-6.5 精神，明文不落盘、日志脱敏）。设备校验 token 后建立会话。
- 10.2b **传输通道**：建议 **WebSocket**（双向、适合音频上行+播放下行+控制信令复用一条连接）；图像可用 **MJPEG-over-HTTP** 或同一 WS 的二进制帧。MQTT 因需 broker、不适合纯点对点，**不采用**。
- 10.2c 连接状态机：`未发现 → 发现 → 配对中 → 已连接 → 工作态 → 断连`；断连自动重连（指数退避），异常在 UI 明确提示。
- 10.2d **单设备连接**：同一时刻仅绑定一台活动设备；已连接列表可保存多台（记住 token），切换需显式选择。
- 10.2e 所有设备通信仅走局域网地址；**不接入任何云端中转**。

### FR-10.3 图像回传（复用 F1，采集源=设备）
- 10.3a 设备摄像头回传帧；主机侧**沿用 F1 抓帧策略**（FR-1.2 默认 8s/帧、FR-1.4 触发式高清抓拍、FR-1.3 VLM 场景识别）。
- 10.3b 帧格式/分辨率：MVP 设备侧输出 JPEG 帧（建议 640~1280 宽），主机不解码视频流；高清抓拍由"触发指令→设备回一帧高分辨率"实现。
- 10.3c 设备能力不足（无摄像头）时，图像相关意图降级为"请对本机摄像头"或禁用视觉能力（据能力位）。
- 10.3d 图像上传云端**仍遵循 NFR-1**：默认本地留存、仅按需将抓帧送已配置 VLM 网关，不上自有服务器。

### FR-10.4 音频上行（复用 F2，麦克风源=设备）
- 10.4a 设备麦克风音频经通道**回传主机**；主机侧**本地跑 VAD + 唤醒词**（FR-2.1a、3.1 L1/L2），维持"唤醒不出网、本地处理"——音频经局域网到电脑后在电脑本地计算，不调用外部唤醒服务。
- 10.4b 上行格式：MVP **PCM 16kHz/16bit/mono** 流（约 256kbps，局域网可承受）；带宽优化列为**待确认项**（设备侧轻量 VAD 门控只上行有效语音段，或 Opus 压缩）。
- 10.4c STT/TTS 仍走 F6 网关（3.3）；唤醒后进入 L4 连续对话窗逻辑不变。
- 10.4d **自我拾音处理**：见 FR-10.6；当拾音与发声同处设备侧时按半双工暂停上行，产品级再上 AEC（与 3.3 同一约束的延伸）。

### FR-10.5 大模型处理（复用 F6 网关，设备=IO 前端）
- 10.5a 回传的图像/音频在主机的既有主循环（§6 伪代码）中处理：**与本机载体完全一致**地经 F6 网关适配层调用 VLM/LLM/决策/STT/TTS。
- 10.5b **不新增厂商绑定、不新增计费路径**；设备模式的所有请求计入同一 FR-6.6 成本看板与 NFR-3 熔断。
- 10.5c **严禁自动计费探测**：任何对网关的请求仅由用户动作（唤醒/指令/抓拍/讲解）触发，不因"设备已连接"而自发调用（沿用既有硬约束）。
- 10.5d Agent 深任务照常路由 F8；结果按音响路径播放、按 F7 讲解画布展示（画布仍显示在电脑端）。

### FR-10.6 音响输出路径（本方案关键需求）
> 决定"TTS 从哪个扬声器出声"，并与拾音端联动以避免回声。

- 10.6a **路径一：电脑音响**——TTS 在主机合成（本地 `say` / Edge-TTS / 云 TTS），**由电脑扬声器播放**；设备仅作上行采集端（麦克风+摄像头）。此时设备**不需要喇叭**，最简。
- 10.6b **路径二：ESP32 音响**——主机将 TTS 音频（建议 PCM16/16k 或 MP3/Opus）**下行回传给设备**，由设备 I2S 功放+喇叭播放。要求固件具备音频播放能力（能力位 🔊）。
- 10.6c **可选性由设备能力决定**：设备无喇叭时，路径二不可用，设置项置灰并提示；设备无麦克风时，路径一/二下的上行仍不可用（据能力位组合处理）。
- 10.6d **设置入口**：在「智能硬件」Tab 与设置页均提供"声音输出：电脑 / 设备"选择；切换即时生效、无需重启（对齐 AC-8 的即时性）。
- 10.6e **回声/半双工策略（组合矩阵）**：

  | 拾音端 | 发声端 | 回声风险 | 处理 |
  |------|------|------|------|
  | 设备麦 | 电脑音响 | 低（异源） | 常规：播报期暂停设备上行（半双工） |
  | 设备麦 | 设备喇叭 | 高（同源近场） | **必须设备侧半双工**：播放期间停止采集；产品级上设备/主机 AEC |
  | 本机麦 | 电脑音响 | 现状 | 沿用 F2 现有半双工 |

- 10.6f **输出路径为设备级持久化配置**（记住上次选择），非会话级临时。

### FR-10.7 固件接口契约与参考固件（本期交付项）
- 10.7a **主机↔设备最小协议**（JSON 控制帧 + 二进制媒体帧，复用单条 WebSocket）：
  - 控制信令：`hello`（上报 设备ID/固件版/能力位📷🎤🔊/建议采样率）、`auth{token}`→`auth_ok/auth_fail`、`config{...}`（下行播放格式/采样率、上行采样率）、`stream.image{on,hd?}`、`stream.audio{on}`、`play.begin/play.chunk/play.end`（TTS 下行）、`ping/state`、`error{code,msg}`。
  - 下行操控指令（电脑远程控制设备，FR-10.10）：`cmd.session{action:start|stop|pause|resume}`（开始上课/下课/暂停/继续→切设备采集态）、`cmd.capture{hd?}`（触发一帧）、`cmd.volume{n}`/`cmd.mute{on}`、`cmd.led{state}`、`cmd.cue{sound}`（"我在听"提示音）、`cmd.speak{text|audioRef}`（主动播报）、`cmd.power{sleep|wake}`、`cmd.reboot`、`cmd.info`（固件版/RSSI/健康）；设备回 `ack{n}/{code}` 确认。
  - 二进制帧：图像=JPEG（宽 640~1280）；音频上行=PCM16/16k/mono 分块；音频下行=PCM16/16k 或 MP3/Opus（设备解码 I2S 播放）。
- 10.7b **接口契约文档随实现产出**（供固件侧对接），主机侧不假设未约定的能力。
- 10.7c **参考固件（纳入本期）**：产出一份可烧录的 ESP32-S3 参考固件示例（配网 + mDNS 广播 + token 鉴权 + 摄像头帧上行 + 麦克风流上行 + I2S 播放下行），用于**打通端到端**；固件不内置任何真实 token/密钥，配网时一次性注入。若你已有现成固件/板型引脚图，请提供以对齐上述契约。

### FR-10.8 设置与配置面板
- 10.8a 设备管理：扫描/连接/断开/删除已配对设备、查看能力与状态。
- 10.8b 音频输出路径选择（10.6d）；上行格式与（可选）设备侧 VAD 门控开关。
- 10.8c Token/PSK 录入与更新（存 Keychain/0600）。
- 10.8d 配置导入导出沿用 FR-6.8（**不含密钥/token**）。

### FR-10.9 安全与隐私
- 10.9a 设备通信仅局域网；token 鉴权；不上传自有服务器（NFR-1）。
- 10.9b 音视频默认本地留存、可关画面留存（NFR-1）。
- 10.9c 凭证（token/Key）一律本机 0600 / Keychain，包体与示例不含任何真实凭证（与全局分发约束一致）。
- 10.9d 学习端/儿童侧不暴露设备管理入口（对齐 FR-5.2）。

### FR-10.10 远程控制（电脑端下行操控设备）
**定位：电脑端是编排大脑，会话状态以电脑端为准；ESP32 是"薄 IO + 执行器"，可被电脑端下行指令远程驱动。设备可能位于另一房间（同 WiFi），故称"远程"——仅局域网、需鉴权、不上云。**

- 10.10a **会话控制下发**：电脑端可发"开始上课/下课/暂停/继续"，驱动设备进入/退出采集上行工作态（idle 时停上行以省电/省带宽，对齐 NFR-8）；等同 3.2 语音会话控制，形成**语音 + 电脑操作双入口**。
- 10.10b **触发抓拍**：远程令设备回传一帧高清（等同 FR-1.4）。
- 10.10c **反馈与播报**：控制设备状态灯/「我在听」提示音（配合 FR-2.1a）；可由电脑端主动下发一段 TTS 到设备播放（配合 FR-10.6 路径二，如"该休息一下了"）。
- 10.10d **音量/静音**：远程调设备喇叭音量、静音（路径二可用时）。
- 10.10e **设备维护**：休眠/唤醒、重启、查询固件版本/RSSI/健康状态。
- 10.10f **一致性与安全**：所有下行操控走 FR-10.2 已鉴权会话（token）；指令带序号并回 `ack`，失败可重放；**不接受任何来自公网/云端的控制**（NFR-1）。控制动作若涉及网关调用（如主动播报需 TTS），仍守"不自动计费、仅用户动作触发"约束。
- 10.10g **儿童侧边界**：远程操控入口在智能硬件 Tab/设置（家长/操作端），学习端孩子界面不暴露对设备的破坏性控制（下课等安全指令仍可语音直达）。

## 6. 技术架构补充（并入主 PRD §6）

新增一行：

| 层 | 选型 | 负责需求 |
|------|------|------|
| 智能硬件接入（新增） | mDNS/Bonjour 发现 + UDP 广播兜底 + 手动 IP；WebSocket 双向控制/音频 + MJPEG/二进制帧图像；共享 token 鉴权（Keychain/0600）；主机侧本地 VAD/唤醒；TTS 输出双路由（电脑 扬声器 / 下行至设备 I2S）；设备能力位驱动 UI 可选性 | F10、FR-10.x |

**外设主循环（在原 §6 伪基础上替换 IO 源）：**

```
connect(device): scan(mdns/udp) -> auth(token) -> working
while 上课中:
    audio_up = device.audio_stream()          # 上行 PCM16/16k（或设备侧VAD门控）
    if wake_word(audio_up) or 直通指令:        # 唤醒/VAD 仍在主机本地跑
        text = stt(audio_up, F6网关)
        intent = llm_normalize(text)
        if intent.needs_vision:
            frame = device.image_frame(hd?)   # 替代 camera.snapshot()
            context = vlm(frame, task)
        reply = tutor_llm(...)  or  agent.run(...)   # F8 不变
        route = audio_output_route            # 'pc' | 'device'（FR-10.6d）
        audio = tts(reply, F6网关)
        if route == 'pc': play_on_pc(audio)          # 播报期暂停上行
        else: device.play(audio)                      # 下行到设备喇叭；同源须半双工
```

| AC-21 | ESP32 与电脑同 WiFi，进入智能硬件 Tab 并扫描 | 在设备开机 ≤10s 内于列表发现该设备，显示名称/IP/能力标签（📷🎤🔊） |
| AC-22 | 选择设备并输入正确 token 连接 | 进入"已连接"；token 错误时明确拒绝且提示；连接状态可持久（重连恢复） |
| AC-23 | 连接后对孩子设备说话并问"这题不会" | 由**设备麦**上行、主机本地唤醒→STT→VLM 读题→引导；≤5s 完成单轮；**回复不含答案**（对齐 FR-3.1） |
| AC-24 | 输出路径=电脑音响 | TTS 从电脑扬声器出声；设备不播放；播报期间设备上行暂停（无自问自答） |
| AC-25 | 输出路径=ESP32 音响（设备具备🔊） | 主机将 TTS 音频下行、由设备喇叭播放；切换即时生效无需重启；设备无🔊时该选项置灰不可选 |
| AC-26 | 设备+喇叭同源，AI 播报时 | 设备播放期间采集停止（半双工），不出现回声自触发 |
| AC-27 | 整个设备会话的成本 | 全部请求走 F6 网关并计入成本看板；连接动作本身不触发任何网关调用（无自动计费） |
| AC-28 | 拔网/断设备 | 明确提示"设备断开"并自动重连；AI 部分告知离线，本地唤醒仍可用（对齐 AC-6/NFR-2） |
| AC-29 | 电脑端在智能硬件 Tab 点"开始上课" | ≤1s 内设备进入采集上行（收到 ack）；点"下课"停止上行；同一动作孩子语音说"下课"也等效生效（双入口） |
| AC-30 | 电脑端远程触发"抓拍/音量/提示音/主动播报" | 设备对应执行并回 ack；指令走已鉴权局域网会话；无公网/云端控制通道；涉及 TTS 的主动播报仅在用户动作时触发（不自动计费） |

## 9. 风险与对策（并入 §9）

| 风险 | 等级 | 对策 |
|------|------|------|
| 设备侧同源麦克风+喇叭回声自触发 | 高 | 播放期暂停上行（半双工）；产品级上 AEC（延续 3.3 自我拾音对策） |
| 连续上行音频占带宽/耗电 | 中 | 设备侧轻量 VAD 门控只上行有效语音；或 Opus 压缩（待确认项） |
| ESP32-S3 摄像头画质/帧率有限，手写识别弱 | 中 | 触发式高清帧；不可用时降级为语音引导，或提示改用本机摄像头 |
| 固件接口契约未定 / 固件缺失 | 高 | 先定最小协议（FR-10.7）+ 参考固件示例打通端到端，再逐步完善 |
| mDNS 在某些路由器/防火墙受限 | 中 | UDP 广播 + 手动 IP 双兜底（FR-10.1b/c） |
| 局域网明文 ws 的鉴权与嗅探 | 中 | token 鉴权 + 可选 wss；仅局域网、不上云；凭证 0600/Keychain |
| 电脑端远程误操作/被劫持控制设备 | 中 | 仅局域网、需 token 已鉴权会话、指令带 ack 与序号；学习端不暴露破坏性控制；关闭公网/云端控制面（FR-10.10f/g） |
| 能力位不一致导致选了不可用路径 | 低 | 能力位驱动 UI（无🔊则路径二置灰，FR-10.6c） |

## 10. 决策记录

**已确认（用户 2026-11-04 拍板）：**
- **D1 目标硬件同时带 摄像头 + 麦克风 + 喇叭** → "电脑音响"与"ESP32 音响"两条输出路径均可用；能力位机制仍保留以兼容其它板型（FR-10.6c）。
- **D2 接受**"设备常驻把音频持续回传、唤醒/VAD 在电脑本地跑"的形态（守住唤醒不出网，FR-10.4a）。
- **D3 参考固件纳入本期实现范围**：由我产出可烧录的 ESP32-S3 参考固件示例并打通端到端（FR-10.7c）；若你已有板型/引脚/现成固件可一并提供以对齐契约。

**建议默认（如无异议即按此实现，均可在最终确认时否决）：**
- 发现：**mDNS 为主 + UDP 广播 + 手动 IP 兜底**（FR-10.1a~c）。
- 传输：**单条 WebSocket** 复用控制 + 音频上下行；图像走同连接的二进制帧（FR-10.2b）。
- 上行音频：MVP 走 **PCM16/16k/mono 连续流**；带宽吃紧再叠加**设备侧 VAD 门控 / Opus**（NFR-8）。
- 配对鉴权：**一次性共享 Token**（存 Keychain/0600），仅局域网、不上云（FR-10.2a）。
- 与"端"的关系：智能硬件 = 采集/发声**通道切换**，叠加在学习端/Agent 之上，**非独立重写的界面**（§3）。
