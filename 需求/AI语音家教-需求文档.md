## 1. 产品定位

面向 homeschool / 家庭辅导场景的 **语音优先 AI 家教**：

- 孩子坐在书桌前写作业，摄像头对准桌面（作业本/课本）。
- AI 通过摄像头持续观察学习现场，通过麦克风倾听孩子说话。
- 孩子全程**用说话的方式控制和使用**：不需要碰鼠标键盘。
- AI 用语音回应（读题、提示、鼓励、纠音），像一位坐在旁边的家庭教师。
- 课后自动生成学习报告给家长。

**一句话描述：一个不会累、看得见作业、听得懂说话、只开口引导不给答案的 AI 家教。**

## 2. 用户角色与场景

| 角色 | 描述 | 使用方式 |
|------|------|------|
| 孩子（主用户） | 6~15 岁，写作业/练英语 | 全程语音交互，不接触键鼠 |
| 家长（配置者/消费者） | 一次性配置，课后看报告 | 首次向导配置 + 每日报告查看 |

### 2.1 三端体验（本产品体验结构）

| 端 | 面向 | 定位 | 与其他端关系 |
|------|------|------|------|
| **沉浸式学习**（学习端） | 孩子 | 日常写作业的极简语音界面（摄像头监看+语音交互）；顶层两按钮之一 | 轻问答就地解决；需深度引导/技能/知识检索时→调用 Agent |
| **Agent**（Agent端） | 孩子/家长 | 可主动对话的"AI 家教智能体"工作台，**直接复用 DeepTutor 原生界面**（左模块栏+中央对话+composer）；底层为 F8 DeepTutor 主引擎 | 被学习端以语音指令唤起，也可在设置中配置；为学习提供智能底座 |
| **设置**（原管理端） | 家长 | 网关/知识库/记忆/技能/报告等所有配置，**直接复用 DeepTutor 原生设置页并叠加本产品功能块**；经顶栏齿轮进入 | 向 Agent 下发模型网关、知识库、技能、记忆策略 |

> **命名与导航（v0.11）：** "管理端"更名为"设置"；顶层仅"沉浸式学习 / Agent"两个切换按钮 + 右侧"设置"齿轮，取消宽侧栏。下文 FR 中出现的"管理端"均等同"设置"。

> **部分学习需要调用 Agent端 完成：** 学习端内嵌的轻推理（意图归一化、简单应答）不启 Agent；一旦需要多步解题、苏格拉底引导、知识库检索、技能执行、生成讲解网页/视频，则路由到 Agent端（F8），结果回传到学习端进行语音 + 画布输出。

**典型场景（用户故事）：**

- US-01 上课：孩子说"开始上课"→ App 进入监看模式，摄像头开始定时抓帧。
- US-02 求助：孩子做数学卡住，说"老师，这道题我不会"→ AI 通过摄像头读题，给苏格拉底式提示（不给答案）。
- US-03 检查：孩子说"帮我检查这一页"→ 摄像头拍当前页，AI 指出第几题可能有问题、只说思路。
- US-04 英语沉浸：英语模式下，孩子指着桌上任何东西问"这是什么"→ AI 用英文回答（名词 + 3 个形容词 + 例句），并纠正孩子发音。
- US-05 状态关怀：连续观察 2 分钟无动笔 → AI 主动语音询问"是累了还是卡住了？"。
- US-06 下课：孩子说"下课"→ 停止监看，生成今日学习报告（专注时长、卡点、错题、建议）。
- US-07 家长复盘：家长打开管理端，看到今日报告、回放关键片段。

## 3. 核心交互设计：语音控制（本产品最重要的需求）

### 3.1 交互模式

采用 **"唤醒词 + 免唤醒关键指令" 混合模式**（唤醒词为标配触发方式，**不提供按键说话（push-to-talk）降级模式**，全程免碰键鼠）：

| 层级 | 机制 | 说明 |
|------|------|------|
| L1 常驻监听 | VAD（语音活动检测）持续听 | 只在本地跑，不上传，用于检测说话 |
| L2 唤醒词 | "小老师"（可自定义），自 v0.1 原型起即启用 | 唤醒后才进入指令解析；本地小模型，不出网 |
| L3 直通指令 | "暂停 / 下课 / 安静" 等安全指令 | 免唤醒直接生效（任何时候喊"下课"都停止） |
| L4 对话模式 | 唤醒后进入 10 秒连续对话窗 | 孩子可连续追问，无需每句都喊唤醒词 |

### 3.2 语音指令表（v1 指令集）

| 类别 | 指令（口语化说法均识别） | 系统行为 |
|------|------|------|
| 会话控制 | "开始上课 / 开始学习" | 进入监看模式，摄像头开始抓帧 |
| 会话控制 | "下课 / 结束了 / 我写完了" | 停止监看，生成学习报告 |
| 会话控制 | "暂停一下 / 我去喝水" | 暂停监看与语音，恢复需"继续" |
| 求助类 | "这题不会 / 这道题怎么写 / 给我个提示" | 读题 → 苏格拉底式提示，不给答案 |
| 求助类 | "下一步呢 / 再提示一下" | 递进式提示（提示分 3 级，逐级加深） |
| 检查类 | "检查一下 / 看看我写的对不对" | 抓帧识别手写内容 → 指出可疑题目 → 只指出不判死 |
| 状态类 | "我累了 / 休息一下" | 记录状态，暂停，温和鼓励 |
| 朗读类 | "读一下这道题 / 再说一遍" | TTS 重读，语速可调 |
| 讲解类 | "打开讲解 / 演示一下 / 这题怎么解出来的 / 生成图解" | 语音同步讲解 + 在学习端渲染**解题讲解网页**（逐步动画，经 F7）；可选导出视频 |
| Agent 调用 | "打开家教 / 老师帮我算 / 查一下资料 / 用XX技能" | 路由到 **Agent端（F8）**：多步解题/知识检索/技能执行；结果回传语音+讲解画布播报 |
| 模式切换 | "英语模式 / 中文模式" | 切换 AI 回复语言（英语模式下全英文回复） |
| 音量语速 | "大声一点 / 说慢一点" | 调整 TTS 参数 |
| 打断 | 任何时候说"停 / 等等" | 立即停止当前 TTS 播报（barge-in） |

**指令解析规则：** 允许自然口语变体（"这题咋做""帮我看看第三题"），由 LLM 做意图归一化，不依赖关键词精确匹配。

### 3.3 语音链路技术要求

| 环节 | MVP 方案 | 进阶方案 |
|------|------|------|
| 采集 | 单麦克风，16kHz | 麦克风阵列 + 回声消除（AEC） |
| VAD | 本地 WebRTC VAD / Silero VAD | 同左 |
| STT | 云端流式识别（可用实时 API） | 本地 Whisper（faster-whisper，中等配置可跑） |
| 唤醒词 | 本地小模型（openWakeWord / Porcupine） | 同左 |
| TTS | macOS 系统 `say`（零成本起步） | 云端高质量童声 TTS / Edge-TTS |
| 回声抑制（关键） | **半双工**：TTS 播报期间暂停识别（避免 AI 自己听到自己） | AEC 全双工 |
| 打断 | 半双工下用"音量突变检测"近似实现 | 真正 barge-in |

> **⚠️ 必须优先解决的技术点：自我拾音。** 扬声器播报时麦克风会录到 TTS 的声音，导致 AI 误触发/自问自答。MVP 用半双工规避，产品级上 AEC。

### 3.4 交互延迟预算（验收硬指标）

| 链路 | 目标延迟 | 说明 |
|------|------|------|
| 唤醒词生效 | ≤ 500 ms | 本地模型，不出网 |
| 说完→ASR 文本 | ≤ 1.5 s | 流式识别 |
| ASR→开始听到 AI 回复 | ≤ 2.5 s | 含意图解析 + 视觉模型（若需看图则 ≤ 4 s） |
| 单轮完整体验 | ≤ 5 s | 超过此值孩子会重复喊，体验崩坏 |
| 讲解网页就绪（本地渲染） | ≤ 2 s | LLM 生成 HTML 后本地预览，无需等视频；与语音回复并行进行 |
| 讲解视频导出 | 异步，不阻塞对话 | MP4 渲染耗时较长，后台生成完再通知，不占用≤5s 预算 |

### 3.5 多模态讲解输出（语音 + 网页 + 视频）

AI 回复不再只靠语音：**同一份讲解内容同时输出为语音、可交互相的解题网页，以及可选的视频**（具体实现见 F7）。网页/视频仍遵守 FR-3.1 红线——只演示思路与步骤，不直给最终答案。

## 4. 功能需求（FR）

### F1 视觉感知

- FR-1.1 摄像头管理：选择设备、分辨率（720p 起）、预览画面。
- FR-1.2 定时抓帧：默认 8 秒/帧（可调 5~30 秒），本地缓存，滚动覆盖。
- FR-1.3 场景识别（调多模态 VLM API）：
  - 识别作业本页面、手写内容、当前写到第几题；
  - 判断状态：动笔中 / 停滞 / 离座 / 疲惫迹象。
- FR-1.4 触发式抓拍：孩子说"看这道题"时立即抓高清帧。
- FR-1.5 双模型仲裁（进阶）：视觉判断"异常事件"（如疑似玩手机）需两次一致才上报，避免冤枉孩子。

### F2 语音交互

- FR-2.1 实现 3.2 全部指令集；指令解析走 LLM 意图归一化。
- FR-2.1a 唤醒词交互（标准方式，全版本必选）：本地离线唤醒（openWakeWord / Porcupine），不出网；唤醒词"小老师"可在管理端自定义/替换；唤醒成功需有短提示音反馈（告知"我在听"）；目标：安静环境唤醒率 ≥ 95%，误唤醒 ≤ 1 次/小时；学习端同步显示唤醒状态指示。
- FR-2.2 TTS 播报：语速 3 档、音量可调、英文模式自动切换英文嗓音。
- FR-2.3 barge-in 打断（MVP 半双工近似）。
- FR-2.4 儿童语音适配：识别准确率目标——安静环境中文指令 ≥ 90%（含口语变体）。
- FR-2.5 静音模式：可关闭 AI 主动说话，只保留被动应答。

### F3 AI 家教决策（提示词工程为主）

- FR-3.1 苏格拉底式引导：**红线——任何情况下不直接给完整答案**；提示分 3 级（方向 → 思路 → 关键步骤）。例外：Agent端 的"直接解题"仅家长/管理端开关场景生效（见 FR-8.3），不影响本红线在孩子侧的适用。
- FR-3.2 英语沉浸模式：识物回答"名词 + 3 形容词 + 1 例句"；孩子说错不批评，给出正确示范并请求复述。
- FR-3.3 主动关怀规则：停滞 > 120 秒 → 温和询问一次（同一问题 10 分钟内不重复）；连续学习 > 40 分钟 → 建议休息。
- FR-3.4 会话记忆：本次课程内记住讲过的题和提示级别；跨次长期记忆由 **F4 记忆子系统（三层可审计）+ Agent端（F8）** 承载，不再是 v2。

### F4 数据、知识库与记忆

- FR-4.1 本地 SQLite：会话记录、抓帧索引、语音指令日志、AI 回复。
- FR-4.2 学习报告（下课自动生成）：专注时长曲线、卡点题目、提示级别统计、错题清单、明日练习建议。
- FR-4.3 错题本：含当时的手写截图，支持导出 PDF。
- FR-4.4 **知识库（资料库）**：本地文档（课本/练习/错题库）入库→向量化→检索增强回答（RAG）。引擎能力参照 DeepTutor 知识中心，至少支持向量检索（可选 PageIndex/GraphRAG/LightRAG 进阶）；知识库由管理端维护，供 Agent端 检索引用。
- FR-4.5 **记忆（新增重点）**：在知识库基础上增加长期记忆，采用类 DeepTutor 三层可审计模型（并借鉴 nanobot Dream 的习惯固化思路）：
  - L1 轨迹：append-only 事件流（每次对话/错点/提示级别使用）；
  - L2 事实：分场景维护的知识点与掌握度（如"小明・分数加法·未掌握"）；
  - L3 综合：跨场景学情画像（薄弱项、偏好、学习进度趋势），驱动个性化与明日建议；
  - 记忆可读/可编辑/可审计（管理端提供视图），支持开关与清空；跨设备不上传（NFR-1）。

### F5 界面与导航（沉浸式学习 / Agent / 设置）

**设计原则：界面简单，且最大化复用 DeepTutor 原生界面，不自研仿制、不留冗余。全 App 顶层仅两个切换按钮——「沉浸式学习」（=学习端，孩子日常）与「Agent」（=Agent端，主动家教）；「设置」（=原管理端，家长/配置）经顶栏右侧齿轮进入。Agent 视图与设置页均直接采用 DeepTutor 自带界面，在其上叠加本产品功能块。**

**零登录原则（FR-5.0）：三端均不需登录，不设账号/注册/登录流程。App 为单机本地应用，打开即进沉浸式学习；Agent 与设置仅通过顶栏入口切换到达，配置保存于本机（沿用 FR-6.5 Keychain 与 FR-6.8 JSON 导入导出）。**

- FR-5.0b **顶层导航（v0.11）**：应用外壳顶部为一条紧凑顶栏——左品牌、中间两个视图切换按钮（沉浸式学习 / Agent）、右设置齿轮。**取消宽侧栏，避免大片空白区域；移除一切自研的冗余导航与界面。**
- FR-5.0c **Agent 视图 = DeepTutor 原生工作台**：**直接复用 DeepTutor 前端界面**（左侧功能模块栏 Chat/知识库/记忆/学习空间 + 中央对话工作区 + 底部带上下文胶囊（模型/知识库/人格/语音）与"+"引用的 composer），不另写一套 UI；本产品能力（讲解画布、语音唤起、红线）以叠加层/配置注入方式接入。

### 6.1 AIPDD 端点登记（v0.3）

|------|------|------|
| 文本（LLM/VLM） | https://app.aipdd.work/api/v1 | 意图归一化、家教对话、读题（FR-1.3） |

**角色映射要求：** VLM/LLM→文本端点；决策（System One 快思考）→systemone 端点；STT→audio/transcriptions；TTS→audio/speech；Embedding/图片/视频为扩展能力，按需在 v2 启用。

- FR-6.1 **OpenAI 兼容协议统一接入**：四大网关均按"自定义 BaseURL + API Key + 可选模型列表"模式接入；厂商差异（鉴权头、模型命名）在适配层抹平，业务代码只面向统一接口。AIPDD 的 systemone/images/videos 等非标准端点由适配层单独封装，统一走同一接口暴露给业务层。
- FR-6.1a **BaseURL 自动拉取模型**：用户输入 BaseURL + API Key 后，自动调用 `GET {BaseURL}/models` 拉取该网关可用模型列表，用户从列表中选择而无需手敲模型名；支持按角色过滤（如标注 vision/audio/embedding 能力的模型），拉取失败时降级为手动输入模型名并给出提示。
- FR-6.2 **按角色映射模型**：VLM（看图）、LLM（意图归一化+家教决策）、决策（systemone 快速通道）、STT、TTS 各角色独立配置"网关 + 端点 + 模型名"（模型名可从 FR-6.1a 拉取列表中选择），允许混搭（例：VLM 走火山引擎豆包视觉，LLM 走 AIPDD 的 DeepSeek，TTS 用本地 `say`）。
- FR-6.3 **多网关并存与故障切换**：每个角色可配置主用+备用网关，主网关连续失败 3 次自动切备用，恢复后切回；切换事件在管理端可见。
- FR-6.4 **配置即测试**：保存配置时自动发一条连通性探测请求（1 次小额调用），实时反馈"该网关该模型当前可用/延迟/单次成本估算"。
- FR-6.5 **密钥安全**：API Key 存入 macOS Keychain，不明文落盘；日志与崩溃上报中脱敏。
- FR-6.6 **成本核算按网关聚合**：每个网关独立统计 token 用量与预估费用，联动 NFR-3 的费用看板与每日熔断上限。
- FR-6.7 **延迟感知选路**：语音链路关键角色（STT/LLM）优先选低延迟网关；视觉角色可容忍较高延迟走低成本网关（见 3.4 延迟预算）。
- FR-6.8 **配置导入导出**：网关配置（不含密钥）支持 JSON 导出/导入，便于多设备或分发场景迁移。

### F7 多模态讲解输出（网页 + 视频，基于 HyperFrames）

**设计原则：讲解不靠"只说"。把 LLM 生成的解题步骤转为 HTML 讲解页（逐步动画演示）与可选的 MP4 视频。统一引入开源引擎 HyperFrames（https://github.com/heygen-com/hyperframes，Apache 2.0）作为渲染核心。**

**为何选 HyperFrames：** 它的创作模型就是"写 HTML”——带 data 属性的普通 HTML 无需构建即可在浏览器直接预览（天然适合"生成网页指导"），同一份 HTML 又能用 headless Chrome + FFmpeg 确定性地渲染成 MP4（自然延伸到"生成视频"）；CLI 默认非交互、专为 agent 而设计，适合由家教 LLM 直接产出 HTML 并驱动渲染；Apache 2.0 无按渲染收费。

- FR-7.1 **网页讲解（主输出）**：家教 LLM 根据读题结果生成解题步骤的 HTML 讲解页（步进式：每一步一条动画/高亮），在学习端讲解画布（内嵌 webview）展示，可复用 `@hyperframes/player` 的 `<hyperframes-player>` 组件。无构建步骤，本地瞬时预览（满足 3.4 ≤2s）。
- FR-7.2 **视频讲解（可选导出）**：将同一份 HTML 讲解页通过 HyperFrames CLI （`npx hyperframes render`）渲染为 MP4，用于错题本/日报回放/离线回看；异步后台渲染，不阻塞当前语音对话（见 3.4）。
- FR-7.3 **链路**：`VLM 读题 → LLM 生成讲解步骤（受 FR-3.1 红线约束）→ 渲染为 HTML（模板/组件库）→ webview 展示 →（按需）渲染 MP4`，与语音 TTS 并行。
- FR-7.4 **模板与组件库**：优先使用 HyperFrames Catalog（`npx hyperframes add`）的现成块（标题/步骤/图表/字幕），避免 LLM 自由生成不合法 HTML；建立"数学/英语/常规题型"讲解模板集。
- FR-7.5 **运行依赖**：需 Node.js 22+ 与 FFmpeg。随 App  bundled（Tauri 侧作为本地子进程调用），用户无需手动安装；启动前自检环境，缺失时降级为"仅语音+静态图片"并提示。
- FR-7.6 **资源与稳定性**：headless Chrome 渲染为瞬时峰值开销，讲解画布关闭时释放；遵守 NFR-5，渲染子进程不能拉高常驻内存，并受 NFR-4 稳定性约束。
- FR-7.7 **内容安全**：讲解页/视频同样受 NFR-6 儿童安全约束，仅渲染本地生成的讲解内容，不加载外部不可信脚本。

### F8 Agent 引擎（以 DeepTutor 为主引擎升级，借鉴 nanobot）

**集成决策（不双保留）：Agent端 以 DeepTutor（HKUDS）为唯一主引擎做二次升级，不引入 nanobot 代码/进程、不保留两套 agent 运行时。** nanobot 仅作**设计参考**：借鉴其 Dream 习惯固化、轻量网关、定时自动化、多渠道/SDK 等理念，在 DeepTutor 上实现同等能力。

**能力构成（DeepTutor 自带 + 借鉴 nanobot 的二开增强）：**

| 能力 | 形式 | 说明 |
|------|------|------|
| 家教业务能力（多轮引导/解题/Quiz/讲解） | DeepTutor 自带 | agent-native 学习工作区，直接复用 tutoring 能力 |
| 知识库 / 多引擎 RAG | DeepTutor 自带 | Knowledge Center（LlamaIndex/PageIndex/GraphRAG/LightRAG），与 F4 对齐 |
| 三层可审计记忆 | DeepTutor 自带 | Memory L1/L2/L3 + Memory Graph，与 F4 对齐 |
| 本地服务与 SDK / OpenAI 兼容 API | DeepTutor 自带 | 学习端/管理端通过 DeepTutor 本地服务与接口调用 |
| 长期习惯固化（类 Dream） | **借鉴 nanobot，二开实现** | 将反复出现的偏好/错因沉淀为稳定画像（不引入 nanobot 代码） |
| 定时自动化（如每日提醒复习） | **借鉴 nanobot，二开实现** | 基于 DeepTutor 已有能力封装定时任务 |
| 轻量启动/会话治理 | **借鉴 nanobot，二开实现** | 优化本地服务的启动与资源占用 |

- FR-8.1 **本地 Agent 服务**：Agent端 = 本地启动一个 **DeepTutor 服务**（自带后端+前端，默认 `127.0.0.1:3782`），不依赖外部托管；学习端/管理端通过 DeepTutor 的 SDK / OpenAI 兼容 API 调用；**不引入 nanobot 进程**；所有模型请求仍走 **F6 网关适配层**（不绑厂商）。
- FR-8.2 **能力路由**：学习端意图若需多步推理/知识检索/技能执行/生成讲解，则调用 Agent；否则学习端就地处理（降低延迟，遵守 3.4 预算）。
- FR-8.3 **红线与"直接解题"例外**：默认（尤其学习端、面向孩子）Agent 输出受 FR-3.1 约束，只引导不给答案；**但 Agent端 保留"直接解题"例外场景**——家长核对答案、或管理端开启"直接解答模式"时，可调用 DeepTutor Solve 直接给出完整解答。例外必须同时满足：① 仅非儿童场景可用（管理端/家长身份进入，学习端不暴露）；② 管理端显式开关控制（FR-5.6a）；③ 可审计（该次直答记入日志）。
- FR-8.3a **默认安全**："直接解答模式"默认关闭；英语沉浸/主动关怀等学习端场景一律不触发直答。
- FR-8.4 **语音可调用 Agent**：Agent 能被打唤醒后的语音指令直接调用（见 3.2 "Agent 调用"行），STT 文本作为 Agent 输入，Agent 结果回传学习端走 TTS+讲解画布。
- FR-8.5 **与记忆/知识库联动**：Agent 每次交互读写 F4 三层记忆，检索 F4 知识库，实现跨课时个性化（错因回看、薄弱项驱动）。
- FR-8.6 **依赖与集成形态**：以 DeepTutor 为底座二开（需 Python 3.11~3.14 + Node.js 20.9+/22）；不强制修改上游；nanobot 思路仅作参考。
- FR-8.7 **资源隔离**：DeepTutor 服务为独立进程，崩溃不拖垮学习端主界面（NFR-4）；内存预算单列（见 NFR-5 补充）。
- FR-8.8 **桌面端封装（可行）**：DeepTutor 官方已提供 macOS/Windows 桌面 Preview，**已将 Python+Node+完整工作区一起打包**（双击即用）。**落地路径（v0.11 明确）：下载 DeepTutor 源码、基于其代码二开**——本项目桌面端 = 一个壳（Electron）负责启停 DeepTutor 本地服务 + **内嵌 webview 直接承载 DeepTutor 原生的 Agent 工作台与设置页**（不自研 UI），学习端（摄像头+语音主循环）为壳内新增层。需自建构建工作流（官方 artifact 会过期且 release 不含安装器）与代码签名/公证（Windows 预览未签名会弹 SmartScreen）。
- FR-8.9 **上游可同步（可持续拉取更新，v0.13）**：DeepTutor 以**上游依赖**纳入版本管理（优先 git submodule / git subtree，或 fork 后跟踪 upstream），保持与官方仓库可追源。本项目二开采用**“叠加/配置注入/补丁”方式最小化对上游的侵入**（不直接抹改上游文件，自定义层与上游目录隔离），使未来可**直接拉取 DeepTutor 仓库的新版本并同步到本项目**，升级时仅需重放少量本地补丁/适配叠加层。需维护“本地补丁清单/upstream 基线版本”以便每次同步可回归。

### F9 Skill 生态（本地上传 + SkillHub 搜索下载）

**设计原则：Agent 能力以 SKILL 为插件单元可扩展，同时支持本地自定义与从 SkillHub 社区按需拉取。**

- FR-9.1 **本地上传 SKILL**：支持用户将本地 SKILL.md（及其资源）导入 Agent（遵循 DeepTutor 的 skills 目录约定），导入后立即可被 Agent 调用。
- FR-9.2 **SkillHub 关键词搜索**：管理端提供搜索框，用户输入关键词→调用 SkillHub 接口拉取列表：
  - 接口：`GET https://api.skillhub.cn/api/skills?keyword=<关键词>&sortBy=score&pageSize=10`（`keyword` 为搜索词，`sortBy=score` 按评分排序，`pageSize` 分页大小）；
  - 展示返回的技能列表（名称/描述/评分等）供用户选择。
- FR-9.3 **下载到本地使用**：用户从列表选中→下载到本地 skills 目录→经**安全门审查**后启用（参照 DeepTutor 社区导入的安全闸门；不自动执行未审查代码）。
- FR-9.4 **凭证与安全**：搜索/下载接口不内携任何真实密钥；包体与示例不得写入凭证；下载内容需静态扫描（可疑命令/脱密检查）后才上阵。与全局分发安全约束一致。
- FR-9.5 **技能管理**：管理端展示已安装技能列表，支持启用/禁用/删除/更新；学习端不暴露技能管理入口。

## 5. 非功能需求（NFR）

| 编号 | 需求 | 指标/说明 |
|------|------|------|
| NFR-1 | 隐私 | 视频/音频仅本地留存，默认 7 天自动清理；知识库与记忆均存本机不上云；上云仅抓帧图片 + 转写文本调 VLM/LLM，且明确可查；不上传任何数据到自家服务器 |
| NFR-2 | 离线降级 | 断网时：语音控制本地部分（唤醒/VAD/TTS）仍可用，AI 理解与 Agent 部分提示"网络断开" |
| NFR-3 | 成本可视 | 管理端显示当日 API 调用量与预估费用，**按网关分别统计（AIPDD / NewAPI / 火山引擎 / 阿里云）**，支持每日调用上限熔断 |
| NFR-4 | 稳定性 | 连续运行 2 小时无崩溃、无内存泄漏（家长不会重启 App）；Agent 服务崩溃可自恢复不阻塞学习端 |
| NFR-5 | 低资源 | 学习端/管理端（Tauri）常驻内存 ≤ 500MB；**Agent 引擎（DeepTutor 本地服务）为独立进程，内存预算单列**（峰值另计，建议 ≤ 1.5GB，不挤占学习端常驻预算）；本地 Whisper 开启时另计 |
| NFR-6 | 儿童安全 | 内容过滤：拒绝与学习无关的不当请求；不输出评判性语言（"你怎么这么笨"类绝对禁止） |

**主循环伪代码（即上一轮讨论的"自研 Agent 编排层"）：**

```
while 上课中:
    vad_frame = mic.listen()            # L1 常驻
    if wake_word(vad_frame) or 直通指令(vad_frame):
        text = stt(mic, until_silence)  # L4 对话窗
        intent = llm_normalize(text)    # 意图归一化
        if intent.needs_vision:
            frame = camera.snapshot()   # FR-1.4
            context = vlm(frame, task)  # 读题/检查
        reply = tutor_llm(text, context, memory, 提示词红线)   # 轻任务就地处理
        if intent.needs_agent:            # 多步/知识检索/技能→Agent端（F8）
            reply = agent.run(text, context, memory, kb, skills)  # DeepTutor 主引擎
        if intent.needs_explain:          # 讲解类（FR-7.1）
            html = render_explain_html(steps)   # LLM 步骤 → HyperFrames HTML
            webview.show(html)                  # 讲解画布即时预览
            async: hyperframes.render(html) → mp4   # 可选视频，后台异步
        tts.speak(reply, block_mic=True)  # 半双工
        memory.log(turn)
    else:
        if 定时器到点: 后台抓帧 → 状态识别 → 主动关怀判断 (FR-3.3)
```

## 8. 验收标准（关键场景）

| 编号 | 场景 | 通过标准 |
|------|------|------|
| AC-1 | 孩子说"开始上课"→开始写数学作业→说"这题不会" | 3 秒内开始播报读题内容；回复中**不包含答案**，只含引导性提问 |
| AC-2 | AI 播报过程中孩子喊"停" | 1 秒内停止播报，随后能正常听新指令（无自触发） |
| AC-3 | 连续 5 轮"再提示一下" | 提示逐级递进，第 3 级后不再加深，转为建议回顾例题 |
| AC-4 | 英语模式问"桌上那个是什么" | 回复为英文（名词+3 形容词+例句），随后引导孩子复述 |
| AC-5 | 说"下课" | 30 秒内生成日报，含专注时长、卡点列表、关键帧截图 |
| AC-6 | 拔掉网线后说"这题不会" | 语音链路仍响应，明确告知离线 |
| AC-7 | 连续运行 2 小时 | 无崩溃；内存不超过 NFR-5 指标 |
| AC-8 | 在设置中把 VLM 角色从 AIPDD 切到火山引擎并保存 | 3 秒内完成连通性探测并显示可用/延迟/成本估算；后续读题请求走新网关，无需重启 App |
| AC-9 | 断开主网关（改错 BaseURL），保持备用网关正确 | 视觉请求连续失败 3 次后自动切到备用网关并继续服务；管理端出现切换事件记录 |
| AC-10 | 输入 AIPDD BaseURL（https://app.aipdd.work/api/v1）+ API Key | 自动拉取并展示该网关模型列表；选择模型后即完成该角色配置，全程无需手动输入模型名；网络异常时降级为手动输入并提示 |
| AC-11 | 说"这题怎么解出来的，演示一下" | 语音讲解同时，学习端讲解画布 ≤2s 展示解题网页（逐步动画）；网页内容**只含思路与步骤，不含最终答案** |
| AC-12 | 在讲解页生成后请求导出视频 | 后台异步渲染 MP4，不阻塞当前语音对话；完成后在错题本/日报可回放；环境缺 Node/FFmpeg 时提示降级不报错 |
| AC-13 | 学习端说"老师帮我算这题/打开家教" | 路由到 Agent端（F8）完成多步引导，结果回学习端语音+画布播报；Agent 崩溃不影响学习端主界面（FR-8.7） |
| AC-14 | 管理端搜索关键词（如"分数加法"） | 调用 SkillHub 接口返回技能列表；选中下载到本地经安全门审查后启用，下次可被 Agent 调用 |
| AC-15 | 本地上传一个 SKILL.md | 导入后立即可被 Agent 调用；包体不携凭证；学习端不暴露技能管理入口 |
| AC-16 | 打开 App 观察顶层导航 | 仅有"沉浸式学习 / Agent"两个切换按钮 + 右侧设置齿轮，无宽侧栏/空白区；切换即时生效 |
| AC-17 | 进入 Agent 与设置 | 两者均呈现 DeepTutor 原生界面（Agent 为左模块栏+中央对话+composer；设置为 DeepTutor 设置页），其上可见本产品叠加功能块；无自研仿制界面残留 |
| AC-18 | 切换界面语言 | 可选语言与 DeepTutor 一致；Agent/设置/学习端及叠加功能块文案随语言同步切换、术语统一，无自造语言项 |
| AC-19 | DeepTutor 官方发布新版本 | 可直接拉取上游仓库更新并同步本项目；二开叠加层/补丁不被覆盖，升级后可回归；能查看当前 upstream 基线版本与本地补丁清单 |

## 9. 风险与对策

| 风险 | 等级 | 对策 |
|------|------|------|
| 自我拾音导致 AI 自问自答 | 高 | MVP 半双工硬隔离；v1 上 AEC |
| 儿童 ASR 准确率不足（变声、口语化） | 高 | 意图归一化走 LLM 容错；指令表允许自由变体；收集自家孩子的语料微调（v2） |
| 手写识别准确率不足 | 中 | 720p+ 定焦摄像头、触发式高清抓拍；不确定时 AI 主动说"我再看一眼" |
| 延迟超标导致孩子重复喊话 | 中 | 延迟预算纳入验收；视觉与语音并行调用 |
| API 费用失控 | 中 | NFR-3 费用看板（按网关统计）+ 每日调用上限熔断 |
| 四网关协议差异（鉴权头/模型命名/错误码不一致） | 中 | F6 统一 OpenAI 兼容适配层抹平差异；每个网关上线前跑连通性探测用例集 |
| 隐私担忧 | 中 | 默认本地留存 7 天、报告可关画面留存 |
| 孩子用语音指令"套答案"（如"把答案读出来"） | 中 | 提示词红线 + 意图层拦截该类意图，统一转为引导；讲解网页/视频同样只演示步骤不给最终答案 |
| LLM 生成的讲解 HTML 不规范/渲染失败 | 中 | 优先用 HyperFrames Catalog 模板与 lint；失败降级为语音+静态图片（FR-7.5） |
| Node/FFmpeg/Chrome 渲染的运行时/内存开销 | 中 | 包体大小不作约束（用户确认）；依赖随 App bundled；渲染子进程用完即释，不影响学习端常驻内存（FR-7.6、NFR-5） |
| DeepTutor 体量大、与桌面壳集成复杂（启动/二开/签名） | 高 | 包体大小不作约束（用户确认）；**直接复用 DeepTutor 原生 Agent/设置界面（webview 内嵌），不另写 UI**；DeepTutor 为独立进程+启动编排/健康检查；基于源码二开必要模块，不强制改上游；需自建构建工作流与签名/公证 |
| Agent 能力与"不给答案"红线冲突（DeepTutor Solve 会直接解题） | 中 | 孩子侧默认红线不变；直答仅作为家长/管理端开关下的受控例外，需非儿童场景+显式开关+可审计（FR-8.3/5.6a） |
| SkillHub 下载技能含不可信代码/命令 | 高 | 经安全门静态扫描后才启用，不自动执行；沙箱受限权限；与全局凭证/分发安全约束一致（FR-9.3/9.4） |
